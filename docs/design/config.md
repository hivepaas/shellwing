# Configuration files

## Where

The config directory is the platform's, overridable with
`$SHELLWING_CONFIG_DIR`:

| OS | Directory |
| --- | --- |
| Linux | `$XDG_CONFIG_HOME/shellwing` (`~/.config/shellwing`) |
| macOS | `~/Library/Application Support/shellwing` |
| Windows | `%APPDATA%\shellwing` |

```
config.toml       settings; edited by people and by the Settings screen; per device
hosts.toml        hosts and groups; written mostly by the app; synced
snippets.toml     saved commands; synced
themes/*.toml     user themes; copy them between machines freely
vault.db          SQLite: encrypted secrets, wrapped keys, sync state (vault.md)
state/*.json      machine-written, never synced: window layout, recent hosts, restore
```

Files are split by **who writes them** and **whether they sync**:

- If people and the app both wrote one big file, every save from the Settings
  screen would risk reordering what a person wrote by hand.
- Settings hold per-device values (font size for this screen, a Windows
  `known_hosts` path); hosts must follow you to every device.

## Formats

TOML for every file a person may read or edit; JSON only under `state/`.

| | JSON | YAML | TOML |
| --- | --- | --- | --- |
| Comments | No (JSONC is non-standard) | Yes | Yes |
| App writes back, keeping comments (Rust) | Hard | No maintained crate | `toml_edit`, as cargo does |
| Hand-editing traps | Commas | Indentation, `no` → false, `1.10` → 1.1 | Few |
| Crate health | `serde_json` excellent | `serde_yaml` archived in 2024 | `toml`, `toml_edit` maintained |

Rules:

- **Reading:** `serde` structs from `toml`.
- **Writing:** the Settings screen edits through `toml_edit`, changing only the
  keys it touched, so comments and order survive.
- **Saving:** write a temp file and rename it, so a crash never leaves a
  half-written file.
- **Live reload:** the files' modification times are checked twice a second,
  and outside edits apply. Polling rather than a file watcher: editors that save
  by replacing the file confuse watchers, and a few `stat` calls cost nothing. A
  file that fails to parse keeps the last good values, and the error is shown
  with the line number.

## Settings precedence

From lowest to highest:

1. Built-in default
2. `config.toml`
3. Group
4. Host
5. Command line

Example: a host's `theme` beats the app theme, and `user@` on the command line
beats the host's `user`.

## hosts.toml

```toml
# Written by shellwing. Editing by hand is fine; comments are kept.
[[group]]
id = "01JAQ7…"
name = "Production"
color = "pink"

[[host]]
id = "01JAQ8…"            # ULID; stays when renamed; sync matches on it
name = "api-1"
alias = "api1"            # `shellwing api1`
address = "10.0.1.11"
port = 22
user = "deploy"
group = "Production"
tags = ["api", "docker"]
jump = ["edge", "bastion"]                          # names of other hosts, outermost first
auth = { method = "key", key = "vault:01JAQ9…" }    # references only; secrets live in the vault
theme = "crimsonEmber"
run = "cd ~/apps/api && exec $SHELL -l"
local_only = false        # true: never synced, even when slots are free
```

- `id`s are generated by the app. A host written by hand without one gets an
  `id` on the next save.
- Sync versions and timestamps live in `vault.db`, not here, so the file stays
  readable.
- Hosts from `~/.ssh/config` show in the sidebar as read-only. "Copy to my hosts"
  turns one into an entry here, after which it can get a color, a group, a
  theme or a saved password.

## What syncs

| File | Syncs |
| --- | --- |
| `hosts.toml`, `snippets.toml`, the vault | Yes |
| `config.toml` | Yes, unless `[sync] settings = false`: the settings that are not the device's own (`settings_sync::SYNCED`), one vault record with a field per setting. The sync folder, log folder, local shell and editor stay per device. |
| `themes/` | Only themes a synced host or the synced appearance refers to |
| `state/` | Never |

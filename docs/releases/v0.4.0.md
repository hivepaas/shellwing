AI access: give Claude Code, Codex or any MCP agent the hosts it needs, never your keys. It runs commands, reads and writes files, reads your notes and runs your snippets, while risky commands wait for you. Plus Run on hosts, for a command or a script on many hosts at once.

## Upgrade notes

- **One shellwing per config directory.** Starting shellwing while it is already open brings the open window forward instead of opening a second one. `shellwing user@host` opens that host in a new tab there. To open a second app on purpose, set `SHELLWING_SECOND_INSTANCE=1`.
- **shellwing listens for AI clients** on a socket only you can open (`state/mcp.sock` in the config directory, or a named pipe on Windows). No agent reaches anything until you add a client in *Settings › AI* and give it hosts.
- **The palette goes to a host's tab.** Choosing a host in the palette with Enter now does what a click in the host list does: it shows that host's last tab. **Ctrl+Enter** (Cmd+Enter) opens a new tab.
- **A newer version shows as a badge on the title bar** (*Update available*, or *Restart to update*), as in packwing. The row over the terminals is gone.

## AI access

Agents reach the hosts you give them over the [Model Context Protocol](https://modelcontextprotocol.io). *Settings › AI › Add client* shows the config to paste into Claude Code, Claude Desktop, Codex CLI, Cursor, VS Code, Windsurf, Zed, Gemini CLI, Cline, or any other MCP client. `shellwing mcp` is the command the client starts.

- **Hosts, not credentials.** shellwing signs in for the agent with what you saved: the vault's passwords and keys, your agent's keys, an organization's certificate. The agent never sees a key, a password or a passphrase.
- **You choose what it may do, host by host:** run commands, read files, write files, read your notes, add to them, use your snippets. A grant lasts until you take it back, while shellwing is open, or for an hour or eight.
  - Give many hosts at once, or a whole group.
  - **Pause** a host or a whole client, and resume it as it was. **Take back** ends it.
- **Risky commands wait for you.** By default, a command with words from the risky list (`rm -rf`, `systemctl stop`, `drop`…) waits until you allow it. A grant can instead ask for every command, or run freely.
  - Writing a file, adding to a note and suggesting a snippet wait as well.
  - The title bar shows an amber button with how many commands wait. A notice says when one comes in.
- **In the background, or through a tab.** In the background, commands run on a connection of the agent's own. Through a tab, they are typed into a terminal you see, one at a time, with a strip that pauses the agent or takes its access back.
- **AI activity** keeps every command and what it printed, drawn as a terminal in your theme, and lets you stop any of them.
  - It is kept on this computer in 10 MB files, up to the size you choose in *Settings › AI* (32 MB unless set). *Clear…* empties it.
  - Agents can read back what they ran before (`activity`), on the hosts they still have.
- **Files.** `list_dir`, `read_file` and `write_file` work over SFTP. `upload` and `download` copy a file or a folder between this computer and a host without its bytes going through the agent. They work only within the local folders you give a client, and never reach `~/.ssh`, the vault or the like.
- **Your notes and snippets as context.**
  - An agent reads your notes about a host (never a sensitive one) and adds what it found to them, never changing what is there.
  - It lists and runs the snippets you keep for a host, filling in only values that cannot change the command. It can also suggest a snippet for you to keep.
  - A snippet that needs environments runs with their values sent by shellwing; the agent never sees them, and every such run waits for you.
  - A note about no host reaches agents only when you tick *Show to AI*.
- **sudo.** A command run with `sudo` waits for you to type sudo's password, or to use the one the vault keeps for the host. The agent never sees it. *Remember it for N minutes* lets the next ones go.
- **A pane you let it read.** *Let AI Read This Pane…* in a pane's menu lets a client read that pane's text for 15 minutes. The pane shows a violet edge while it lasts.
- **A new host key waits for you.** On a host not in `known_hosts`, the agent's command waits in AI activity, which shows the key's fingerprint. Trust it, or refuse it. The agent never trusts a key itself.
- **Stopping works on the host.** Stopping a command sends it TERM, then KILL, so a command that prints nothing no longer runs on. Quitting shellwing stops what still runs.

## Run on hosts

- **A command or a script on many hosts at once**, in a tab of its own: from *Actions* at the top of the host list, a group's ▶, hosts picked with Ctrl+click, or the palette.
- Each question is asked once before anything runs: passwords, passphrases, a new host key, and sudo's password. A script's `#!` picks its interpreter (sh, bash, python3, PowerShell…).
- Results come **by output** (hosts with the same output grouped) or **by host**, drawn as a terminal in your theme. What a host prints shows while it runs.
- Choose how many hosts run at once, a time limit, and *one host first*. *Run again*, or *Again on the failed*.
- Drag an output's bottom edge to make it taller. **Stop** ends the command on the hosts, not only in shellwing.

## Files, tabs and settings

- **The Files panel opens in the shell's current folder**, when the shell reports it (OSC 7, or a title such as `user@host: ~/apps`).
- **Drop files on the terminal** to upload them into that folder. On a local shell, a drop types their paths. Drops now also work right after typing.
- **Tabs share the title bar:** narrower as there are more, then their icons alone (✕ under the pointer), then scrolled.
- **App colors come in styles:** 8 light (Daylight, Paper, High contrast…) and 10 dark (Dusk, Graphite, Midnight…), in *Settings › Appearance*.
- **A key file only an administrator can read** (such as `/root/.ssh/id_ed25519`) can be read once into the vault, after the system asks for an administrator's password. On Linux and macOS.
- **Host icons:** Windows, and a Cloud section (AWS, Azure, Google Cloud, DigitalOcean, Hetzner and 11 more) to choose from.
- **Settings:** every page as wide as the others, longer setting names, and a scroll bar on a long page.
- **The snippet window's side** can be dragged wider. So can AI activity's list.
- **About** shows the author's other apps, tracewing and packwing.

## Fixes and more

- **The host list scrolls** with many hosts, instead of squeezing its rows, and has a scroll bar that widens under the pointer.
- **A selection dragged out of the terminal** keeps following the pointer, and scrolls the history when held above or below.
- **The terminal's scroll bar** keeps hold of its thumb when the pointer leaves the terminal.
- **On Windows, `shellwing mcp` ends** once its client closes it, instead of running on.

## The first time it opens

- **macOS:** signed and notarized. macOS asks once whether to open an app from the internet and says Apple checked it. Choose **Open**.
- **Windows:** this release is not signed. SmartScreen says *Windows protected your PC*: choose **More info › Run anyway**.
- **Linux:** make the AppImage executable (`chmod +x`) and run it. Where FUSE is missing, run it with `--appimage-extract-and-run`. The `.rpm` is not signed, so `dnf` skips its signature check with a warning, and `zypper` needs `--no-gpg-checks`.

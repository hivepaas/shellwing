Packages for more Linux systems, and a clearer way to hear about updates and install them

## Upgrade notes

- **If you installed from the `.deb`:** v0.2.0 can't show the new update commands yet, so install this one by hand once. Download the `.deb` and run `sudo apt install ./shellwing_0.2.1_amd64.deb` (`arm64` on ARM). It upgrades in place, so there is nothing to remove first. From this version on, the app shows you the commands.
- **AppImage, macOS and Windows installer:** update from *Settings › About* as usual.

## Updates

- **A row over your tabs' panes** says when a new version is out, with **Update**, **Skip this version** and a close button that lasts until the next start. It never takes the keyboard, so it can appear mid-session without catching what you type.
- **The `.deb` and `.rpm` get their own instructions.** *Settings › About* shows the commands for your system (`apt`, `dnf` or `zypper`), which check the download against the signed list of releases. Copy them, or open them in a local terminal, where they wait for you to press Enter.
- **The Updates section moved up** in *Settings › About*, so you no longer scroll to it.

## Packages

- **An `.rpm` for Fedora, openSUSE and similar systems.** Tried on Fedora, openSUSE Tumbleweed and Leap 15.6. It needs glibc 2.35 or newer, so systems such as Rocky Linux 9 and Amazon Linux 2023 refuse it at install. The AppImage needs the same glibc.

`SHA256SUMS` lists every file's SHA-256.

## The first time it opens

- **macOS**: signed and notarized. macOS asks once whether to open an app from the internet, and says Apple checked it: choose **Open**.
- **Windows**: this release is not signed. SmartScreen says *Windows protected your PC*: **More info › Run anyway**.
- **Linux**: make the AppImage executable (`chmod +x`) and run it; where FUSE is missing, run it with `--appimage-extract-and-run`. The `.rpm` is not signed, so `dnf` skips its signature check with a warning, and `zypper` needs `--no-gpg-checks`.
